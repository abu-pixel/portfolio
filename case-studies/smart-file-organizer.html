Smart File Organizer

A folder watcher that sorts new files by type in real time, plus a PowerShell collector and a small web dashboard for system performance.

01Project overview

Smart File Organizer watches folders, sorts incoming files by type and reports system performance through a small web dashboard. The sorting logic is Python, the real-time watcher is Node.js, the system statistics come from a PowerShell script, and the dashboard is plain HTML, CSS and JavaScript.

02The real problem

I kept losing track of files scattered across folders, especially downloads. Sorting them manually is repetitive and easy to skip. I wanted the machine to handle the boring classification work and give me a simple view of what the tool was doing and how the system was behaving.

03Target users and their needs

  • People whose downloads and working folders fill up with mixed file types.
  • They need new files sorted automatically, without a manual cleanup session.
  • They need a visible dashboard so the automation is understandable rather than mysterious.
  • For me: practice combining several small tools into one coherent workflow.

04System architecture

05Technology selection and justification

  • Python handles the sorting rules because file operations are short, readable scripts in it.
  • Node.js provides the real-time watcher that reacts when a file appears.
  • PowerShell reads Windows system statistics directly, which is what the project needed at the time.
  • Plain HTML, CSS and JavaScript keep the dashboard light enough to serve without a frontend framework.

06Data model

There is no database described for this project. The working data is transient: file paths and extensions during sorting, and periodic system-statistic samples for the dashboard. I will not claim persisted historical data or a schema that is not in the repository.

14Security considerations

  • The sorting scripts operate on local filesystem paths, so path handling is the sensitive part of the design.
  • No credentials or account system are described for the tool.
  • The hosted dashboard has no authentication, which is why it should be treated as a demo rather than a management console for real folders.
  • No security audit has been performed or claimed.

15Difficult technical challenges

Combining three small tools written for different runtimes was the main challenge: the watcher has to invoke the sorter reliably, and the stats collector has to feed the dashboard without turning into a full backend. Keeping the dashboard framework-free made the data exchange explicit. Real-time watching also means thinking about duplicate or rapid events rather than just a one-off scan.

16Engineering trade-offs

  • Multiple small tools: each language does what it is good at, in exchange for more moving parts to coordinate.
  • Real-time watcher: immediate sorting, in exchange for handling event bursts carefully.
  • PowerShell for stats: direct Windows access, in exchange for platform specificity.
  • No framework dashboard: light output, in exchange for writing more of the data plumbing by hand.

17Known limitations

  • System-stat collection depends on PowerShell and is therefore Windows-oriented.
  • No authentication on the hosted dashboard demo.
  • No published data-flow reference, tests, screenshots or performance measurements.
  • No described persistence for historical activity or metrics.

18Future development roadmap

Ideas rather than commitments:

  • Document the data flow and the dashboard's exchange format.
  • Add tests for sorting rules and duplicate-event handling.
  • Add optional persistence so sorting activity can be reviewed later.
  • Explore a cross-platform stats collector instead of PowerShell alone.

19Outcomes and measurable results

The portfolio lists 9 users and the dashboard demo is public. The concrete result is an automated flow from a new file appearing to it being sorted by type, with system metrics visible in a browser. I have not measured files processed, time saved or uptime, and none of that is claimed here.

20My contribution

I built Smart File Organizer as a personal project: the Python sorting rules, the Node.js watcher, the PowerShell stats collector and the dashboard. It was a solo exercise in making several small tools behave like one product.
